# SoundCloud transport extraction

SoundCloudTransport owns token exchange, form API requests, provider error mapping and same-origin continuation validation. It supports an injected fetch implementation for repeatable fixtures. Credentials must be provided by the caller and enabled; requests disallow redirects. Token parameters cannot override configured client identity. No request occurs until a caller invokes an operation.

Responses now use streamed byte-budget enforcement (default 4 MiB, configurable up to 16 MiB). Fetch receives a deadline signal (default ten seconds, configurable up to five minutes) that a compliant fetch implementation applies through body consumption. Successful JSON responses must be objects; malformed, truncated or oversized reads fail instead of appearing as empty pages. Unreadable successful write/token receipts are ambiguous_submission and must be reconciled, not blindly retried. Known HTTP errors retain their status classification even with unreadable bodies. Explicit empty-success/ignored-404 responses cancel unused bodies.

Authorization URL, authorization-code and refresh request construction are shared through createAuthorizationUrl, exchangeAuthorizationCode and refreshAuthentication. Authorization URLs use S256 and never include the verifier or client secret. Code exchange uses the configured redirect URI. Missing PKCE is rejected before any request. These compatibility helpers accept caller-provided opaque state and PKCE values: they do not generate, validate, persist or consume state/verifier pairs, prove challenge/verifier correspondence, or prevent replay. The caller must own those controls and attach any workflow-specific error context.

Product capability admission, OAuth state/PKCE lifecycle, credential persistence, upload streams, recovery and canonical storage are not supplied here. Injected fetch implementations must honor abort signals; the transport cannot forcibly stop arbitrary caller code. Byte budgets do not bound transport-internal buffering or exact heap usage. Expiry coercion remains follow-up validation. No automatic retries or provider writes are initiated by constructing the transport. Test credentials and responses are synthetic.
