# SoundCloud normalization

Pure track, timed-comment and activity normalizers preserve the existing connector mapping, provider IDs, quoted tags, numeric/date coercion and activity fallback IDs. Tracks are external metadata references: no canonical audio `content` source is synthesized. Raw payload fields remain available for caller provenance handling and are not a public response projection.

Account, profile, playlist and favourite-user normalizers also preserve the connector mapping. Account lookup requires both provider ID and username and throws invalid_response if incomplete; unidentified playlists/favourite users return null for caller filtering. Profiles retain optional fields and existing metric coercion (including null to zero), not identity validation. URNs take precedence over numeric IDs; raw profile/playlist/favourite payloads remain caller-owned references, not sanitized or cloned public data. Playlist normalization does not fetch member tracks or establish complete pagination.

Activity without a provider event ID now requires an explicit type, actor, track and valid occurrence date before using the existing fallback ID format. Incomplete identity throws ExternalProviderError with invalid_response rather than collapsing unrelated events into a type-only ID or silently filtering them out. Callers must fail the page without advancing its checkpoint. Provider IDs and complete historical fallback IDs retain their format; no stored records are rewritten.

Out-of-range or non-date values now normalize to an absent optional date rather than throwing raw coercion/RangeError exceptions. Activity without a provider ID still requires a valid date and therefore fails with invalid_response when its fallback identity is incomplete. Existing seconds/milliseconds detection, zero handling and valid date formats remain unchanged. This is representability validation, not proof that the provider timestamp is plausible or authoritative.

This is not new provider admission or a strict schema validator. Permissive metric numeric coercion remains; callers must validate hostile payloads. Complete fallback tuples are still not a provider uniqueness guarantee (two events can share a tuple); provider-issued IDs remain preferable. Network requests, credentials, pagination, recovery, publication permissions and storage remain adapter/product responsibilities. Tests use synthetic fixtures, not live provider calls.
